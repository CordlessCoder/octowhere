## What to look for

The mesh review's categories, which the owner has accepted:

- **Structure**: functions or types doing several jobs; state spread over fields that several
  places reset in overlapping subsets; a decision buried in a body that could be a plain,
  testable function.
- **Duplication**: the same encoding, geometry, layout or state machine written more than once.
- **Names and types**: names that collide or mislead; sentinel values where an `Option`
  belongs; positional bools and long argument lists; tuples that want a struct.
- **Unstated invariants and magic numbers**: an ordering, a protocol obligation or a bound the
  types do not enforce and no comment states; literals that should be named.
- **Comments**: ones that restate the code, are stale, or hedge against what would not compile
  (the owner's rule: a comment says what the code cannot). Undefined-behaviour words used for
  anything but UB.
- **Tests**: assertions missing or vacuous, helpers defined several ways, a module with logic
  and no test where a host test is possible.
- **Work and stack**: plain waste, as above. On the board, core 0's stack is shared by every
  task (`AGENTS.md`, "Memory"), so a large frame on the frame loop's or a bus task's path counts.
- **Public surface**: items public with nothing outside using them (grep the other crates and
  `tools/` before saying so).
- **Bugs** found on the way: report them, marked as bugs, first.
